# 副本旧后台浏览器观察记录

日期：2026-10-03。目标为用户提供的副本 `http://127.0.0.1/admin123/#/login`，使用获授权的既有账号。本页记录实际渲染与导航，用于校正[产物解读](28-admin-built-layout-reading.md)，不作为新后台样板通过或全量页面验收的证明。

## 环境与证据范围

- 使用 WSL2/Linux 的 `/usr/bin/google-chrome`，由 Playwright CLI 启动独立、无头、非持久化浏览器上下文；不是 Windows Chrome 或用户既有浏览器会话。
- 桌面为 1440×900；手机为 390×844、登录页另测 320×844；客户导航断点另测 993/992px。未测试平板、触屏、软键盘及其他浏览器。
- 页面加载的 app/Login 等主资源文件名与当前 checkout 对应；未做部署文件字节或 SHA256 比对。
- 本轮登录一次，读取列表/摘要/资料及必要辅助接口，展开搜索、切换资料页、无修改取消、调整视口与滚动。没有提交客户更改、创建角色或客户、支付、服务操作、改配置或发布。
- 登录及旧页面初始化可能产生应用既有的日志、通知和维护副作用；不把此次导航称为无副作用。隔离情况沿用[环境预检](26-admin-pilot-contract.md)，未修复或重新验证。
- 只记录方法、脱敏路径、HTTP/业务状态、标签和几何尺寸。账号凭据、客户字段值、请求体、Cookie、响应全文及会话状态不写入文档。截图遮盖管理员区域、客户数据和表单值；登录截图取自填写凭据之前。
- 本轮没有执行 PHP 或应用命令，也没有刷新 APP_PHP/扩展/worker/Cron 证据。

## 页面关系和实际请求

页面入口为 `/admin123/`，使用 hash 路由。客户 ID 在以下记录中替换为 `{client_id}`，不使用副本实际对象值。

```text
#/login
  → 登录成功 → #/home-page
  → 打开导航所列客户入口 → #/customer-list
  → 点击客户姓名 → #/customer-view/abstract?id={client_id}
  → 个人资料 → #/customer-view/person?id={client_id}
  → 未修改，取消更改 → #/customer-view/abstract?id={client_id}
```

列表加载后的 URL 包含 `?searchObj&page=1&limit=50&order=id&sort=DESC`。这是本次旧页面生成的参数，不是要求新页面照抄空 searchObj。列表与资料页跳转后的读取证据如下；查询值不记录。

| 页面/操作 | 实际方法与路径 | HTTP / 业务 status |
| --- | --- | --- |
| 登录前初始化 | GET `/admin123/login_page`、`/admin123/verify`、`/admin123/community/configLang` | 确认路径；本表不据此认定验证码已启用 |
| 登录提交 | POST `/admin123/login` | 200 / 200 |
| 客户列表 | POST `/admin123/client_list` | 200 / 200 |
| 客户摘要 | GET `/admin123/summary`、`/admin123/credit_limit`、`/admin123/get_user`、`/admin123/certifi_person_detail/{client_id}` | 200 / 200 |
| 资料页重新加载 | GET `/admin123/profile/{client_id}` | 200 / 200 |
| 资料辅助选项 | GET `/admin123/common/get_client_groups`、`/admin123/common/get_sms_country`、`/admin123/common/get_getways` | 200 / 200 |

状态 200 只证明本次对应读取/登录成功，不证明完整返回 schema、数据准确性或所有权限分支通过。缺失 res.php 的静态问题仍需追溯；这些实际 HTTP 成功说明它没有阻断本次路径，不证明依赖问题已修复，也不推定其具体原因。

## 登录排版

背景图铺满页面，白色表单居中；当前实例只显示账号、密码、“记住密码”和登录按钮，没有可见的图形验证码或二次验证码输入框。未改配置或强制开启验证分支。

| 视口 | 表单 x / 宽 | 页面 scrollWidth | 结论 |
| --- | --- | --- | --- |
| 1440×900 | 520 / 400px | 1440px | 表单高约 524px，居中显示 |
| 390×844 | -5 / 400px | 395px | 左侧裁切 5px，右侧超出 5px |
| 320×844 | -40 / 400px | 360px | 左侧裁切 40px，右侧超出 40px |

新设计应使用最大宽度与视口内边距约束，在 320/390px 下验收页面无横向溢出。不能因本次能登录就判手机布局通过。

## 外壳与客户列表排版

首页顶栏高 60px、主区从 y=60 延伸到底部，本次首页不显示侧栏。客户列表桌面显示 200px 侧栏，主区 padding 为 `25px 20px 0px`。这说明外壳随路由变化；此前静态 CSS 中的窄屏 padding 声明也不能代替最终计算样式。

桌面内容顺序：说明/帮助 → 添加客户、高级搜索 → 展开的浅色筛选区 → 表格 → 总条数和分页。高级筛选按多列横向排布；390px 下改为逐项纵向排列，表单与表格外层宽 308px，整页 scrollWidth=390px。手机首屏大部分被已展开筛选占据，表格从接近首屏底部开始；未操作表格内部横向滚动。

本实例表头依次为：ID、姓名、手机号/邮箱、服务、收入/支出、余额、客户分组、状态、销售、信用额（已用/总计）。未出现条件 API 开通时间列；实测首个数据单元格高 45px。信用额与余额是独立列。

展开区标签依次包括销售、客户分组、API状态、QQ、客户状态、手机号、邮箱、公司名、姓名、实名状态，下方为搜索/清空。仅确认可见结构，未验证筛选结果。新设计需保留检索能力，并验收收起/展开时的内容位置和手机表格浏览。

## 客户详情、资料和响应式行为

桌面详情顶部为水平客户子页导航，当前可见客户摘要、个人资料、产品/服务、账单、交易记录、信用管理、工单、日志、API概览、通知日志、附件、跟进状态。其他条件标签不据此判缺失。资料页在相同容器内显示表单，不是独立脱离客户上下文的页面。

993px 使用水平 menu，992px 切换 tabs；等待过渡完成后确认两者分别出现，不把过渡中的 DOM 同时存在当作最终显示。390px 的 tabs 具有左右切换箭头；未逐个点击全部标签。

实际资料分组及顺序为：

| 分组 | 本实例可见字段 | 控件/布局 |
| --- | --- | --- |
| 个人资料 | 姓名、性别、公司、国家、省、地址、邮编、了解途径 | 顶部标签；性别下拉，其余本次为输入控件；未显示自定义字段，不能认定不支持 |
| 账户信息 | 手机、邮箱、QQ、密码 | 手机包含区号选择与输入；未修改或检查密码业务分支 |
| 其他设置 | 支付方式、推荐人、语言、销售、客户分组、状态、接收营销信息、关闭发送邮件短信 | 选择/输入及两个开关；支付方式、推荐人不在账户信息组 |

在 1440px 下普通字段宽 200px、相邻字段起点相差约 220px，每行最多五项；三组纵向排列，组标题横贯内容区。资料容器高 675px、overflow-y=auto，保存/取消位于底部操作区。本次桌面字段量能在主体中展开；更多自定义字段时的滚动仍需单独验收。

手机行为须区分进入方式：

| 进入方式 | 实际布局 | 影响 |
| --- | --- | --- |
| 首次桌面加载，直接缩至 390px | 几何采样中侧栏继续占 200px；主区宽 190px，资料区 x=241、宽 108px；字段仍宽 200px，资料区 overflow-x=hidden | 字段被裁切，无法作为手机布局通过；页面 scrollWidth 仍为 390px，单看全页无溢出会漏掉问题 |
| 已在 390px，重新加载资料页 | 侧栏不显示；主区宽 390px、资料区 x=41/宽 308px，字段宽 200px并逐项排列 | 正常单列，纵向内层滚动；底部保存/取消区约 y=744、高60px |
| 后续在桌面刷新后再次缩至 390px | 最终缩屏截图中侧栏已收起，但仍使用桌面 menu，12 个标签换成三行；不同于手机刷新后的箭头 tabs | 响应式状态并非每次表现相同，不能宣称所有缩屏都固定保留侧栏；具体事件覆盖/状态同步原因未追踪 |

手机可滚到“其他设置”，操作区保持可见。尚未验证软键盘遮挡、最后一项校验提示、选择器弹层或固定操作区覆盖字段。新后台的响应式状态必须随视口实时更新，并对新进入、缩放和菜单开关分别验收，不能依赖刷新。
