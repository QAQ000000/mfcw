# 购物车与结算页面

购物车由 `ViewCartController`、`app/home/controller/CartController.php`、
`app/common/logic/Cart.php` 和 `public/themes/cart/<theme>/` 共同负责。

## 页面流程

```text
商品列表/分类
  -> 产品配置
  -> 购物车摘要
  -> 优惠码与数量调整
  -> 结算/客户登录
  -> 创建订单和账单
  -> 选择支付方式
  -> 支付结果/订单状态
```

| 页面 | 模板 | 布局重点 | 关键状态 |
| --- | --- | --- | --- |
| 商品页 | `product.tpl` | 商品卡片、账期、库存、购买按钮 | 隐藏、停售、无库存、价格加载失败 |
| 配置页 | `configureproduct.tpl` | 配置项表单、价格摘要、继续按钮 | 必填项、配置冲突、库存变化 |
| 摘要页 | `ordersummary.tpl` | 商品明细、周期价格、优惠和税费 | 金额重算、优惠码失效 |
| 购物车 | `viewcart.tpl` | 多商品列表、数量、删除、结算 | 空购物车、数量上限、并发修改 |
| 完成页 | `complete.tpl` | 订单号、支付提示、下一步入口 | 创建成功、待审核、支付中、失败 |

## 必须遵守

- 前端展示价格只是预览；结算接口必须重新读取产品、价格、库存、优惠和客户状态。
- 数量修改、添加/删除商品和优惠码操作成功后刷新摘要，不局部猜测金额。
- 无选中商品时禁用结算，点击/键盘提交处理也必须拦截，不能发送空 `pos`、省略 `pos` 或用 `cart_data` 绕过选择。`settle` 当前在空选或全部无效索引时使用整车商品，混合有效/无效索引时仅使用有效部分；这些不是“未选商品”的拒绝响应。
- `i/pos` 是购物车位置，不是商品 ID。删除、增减商品、刷新、结算后及旧窗口恢复时重新读取整车；索引/商品配置/数量有变化或无法确认时清空选择，要求用户重新勾选，再获取所选摘要。提交前核对每个索引和对应商品、周期、配置、数量；空选、任何失效或错位索引、摘要未完成时不发结算请求。完整顺序及并发限制见[购物车样板](24-first-batch-page-specs.md#f03-购物车与结算)。
- 支付成功页面不能直接宣布服务已开通，应根据订单、账单和服务实际状态显示结果。
- `theme.config` 使用现有扁平键格式；主题切换只影响表现，不改变权限和价格规则。

## 验收

验证未登录浏览、登录后结算、单商品、多商品、配置项、库存不足、无效优惠码、重复提交、
支付取消、支付回调延迟和刷新回到购物车等场景；Q03–Q06 专门验证空选、全部/部分失效索引、删除后的索引重排及旧窗口恢复，必须观察结算请求次数和订单数量。默认、area、province 主题至少检查受
影响的模板和头尾布局。
