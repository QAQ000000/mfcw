# 后台页面

后台入口前缀由 `config("database.admin_application")` 决定，路由由 `data/route/admin.php`
提供，PHP 页面控制器位于 `app/admin/controller/View*.php`；`public/admin/` 编译资源另有
Vue Router 页面，完整静态条目见[路由盘点](22-admin-route-inventory.md)，两套页面关系见
[对应关系](23-admin-page-crosswalk.md)。当前缺少完整后台工程，不能把压缩资源审查当作完整源码审查。

## 页面分组

| 分组 | 页面示例 | 二开重点 |
| --- | --- | --- |
| 仪表盘 | `/index` | 统计卡片、告警、快捷入口和权限 |
| 客户 | `/clients`、客户详情系列页面 | 客户资料、服务、账单、余额、日志和工单 |
| 业务 | `/orders`、`/orderdetail`、`/productlist`、`/cancelrequests` | 订单状态、商品和取消请求 |
| 财务 | `/transactions`、`/invoices`、支付和促销配置 | 金额、权限、回调和审计 |
| 工单 | `/supportticket`、部门、状态和转发配置 | 回复、附件、部门权限 |
| 商品/资源 | `/configproducts`、模块、资源池和上游 API | 产品价格、库存、服务器模块和供应商 |

## 公共页面结构

每个后台页面都应遵循统一外壳：顶部账户和环境信息、侧边菜单、面包屑/页面标题、筛选或
操作工具栏、主内容区、分页/汇总区和全局通知。详情和编辑页面还要提供返回入口、保存状态、
错误回填和操作日志提示。新模板可以改变视觉层级，但不能隐藏必要的权限提示和高风险操作确认。

## 分组页面说明

### 客户页面

客户列表负责搜索、分组、状态和批量操作；客户详情以客户为上下文切换资料、服务、账单、
交易、预存余额、信用额度、工单、日志、附件和邮件。所有子页面必须显示当前客户标识，读取和写入均由后端
再次校验客户权限。

### 业务与商品页面

订单列表、订单详情、产品列表和取消请求围绕订单状态、金额、产品、服务和操作记录展开。
商品配置页面要区分产品基本信息、价格/账期、库存、配置项、服务器模块、上游关联和发布状态；
保存后必须明确哪些字段立即生效，哪些需要清缓存或运行 Cron。

### 财务页面

发票、交易、收款、提现、支付网关、促销、货币和充值配置必须突出金额、状态、时间、客户和
审计信息。支付、退款、余额调整和批量操作属于高风险动作，必须显示确认、权限和结果，不允许
仅通过前端禁用按钮保护。

### 工单页面

工单列表需要筛选状态、部门、优先级和未读；详情需要消息时间线、回复、附件、部门转发、关闭
和评价。部门、状态、自动关闭和转发配置必须与客户工单页面的显示状态一致。

### 资源与上游页面

资源池、手工资源、服务器模块、DCIM、上游财务 API 和同步任务页面要展示连接状态、最近同步、
错误信息和重试入口。密钥和临时凭据只显示脱敏值，操作结果同时写入后台日志。

## 页面验收

逐个后台入口的排版、字段、状态和响应式要求见[后台逐页排版与交互契约](12-admin-page-layout-details.md)。本页保留分组、边界和验收总则，详细页面契约以该文档为准。

每个后台页面都要检查管理员登录、二次验证、菜单权限、接口权限、筛选分页、表单校验、
批量操作、保存失败回填、成功后的刷新和操作日志。产品、订单、账单、客户和上游资源
页面必须使用有权限与无权限管理员各验证一次。

修改编译资源时记录来源、构建方式、文件名和缓存策略；如果只有压缩包或构建产物，先
补齐可追溯的前端源码或明确发布限制，不要直接长期手工编辑压缩文件。
