# 模板重构的数据与兼容迁移

纯模板替换原则上不修改业务表；如果为了新模板增加字段、权限、菜单、状态、资源清单或页面配置，必须按本文件记录迁移。

## 首批确定范围

首批方案继续使用既有客户、商品、订单、账单、主机和工单模型，接口字段不改名。**不需要业务数据库 schema 迁移，不新增升级 SQL**；主题目录和现有主题选择键列入发布记录，回滚恢复键值。此结论仅适用于纯模板方案，不代表新后台菜单/RBAC 或未来新增字段也不需要迁移。

| 兼容对象 | 保留规则 | 具体检查 |
| --- | --- | --- |
| URL/ID | /cart 的 action/pid、账单 id、服务 id、前台工单 tid 和后台工单 id | 链接保持参数，工单两种编号不可替换 |
| 金额 | 预存余额 clients.credit 与 credit_limit 分开 | 相同测试对象新旧展示及报价相同，不重新计算历史账单 |
| 字段层级 | 顶层 list/total、user、currency/products、data 等原结构 | 按接口适配，不批量改成 data.list |
| 枚举 | 保留订单/账单/domainstatus/ticket_status 实际值 | 未知值可显示，不新增部分退款枚举 |
| 缓存与会话 | Session/Token 和 Cookie 机制保持 | 新旧窗口验证登录态与主题选择，不复制运行时缓存作为制品 |
| 权限与菜单 | 原 auth_rule.name、实例授权和部门配置保持 | 如新增规则，单独迁移及最小授权，不以 UI 能力名替换 |

## 变更记录

每次变更写明：表/配置键/权限项、旧值与新值、默认值、是否允许为空、索引、旧数据处理、回滚方式、影响页面和测试数据。迁移进入 `public/upgrade/<version>.sql`，安装库同步更新，保持幂等或由升级器保证只执行一次。

## 兼容原则

- 先增加可选字段或配置，再发布读取逻辑，最后切换写入；避免一次发布同时删除旧字段。
- 旧模板和旧接口在过渡期仍能读取新数据；新模板不能要求历史记录具备不存在的字段。
- 权限新增默认最小授权；高风险权限不能因角色复制或升级自动扩大。
- 菜单、语言键、资源清单和主题配置迁移要保留旧键回退，确认无引用后再清理。
- 订单、账单、余额、库存、主机和工单数据不通过模板脚本重算或批量覆盖。

## 升级检查

迁移前备份数据库、配置、主题、插件、上传和下载；在隔离 MySQL/MariaDB 执行一次和重复执行测试。迁移后检查表、索引、配置版本、权限、页面读取、写入、队列和 Cron。失败时保留日志和数据库快照，按部署文档执行恢复，不重复执行未知 SQL。

## 不应迁移的内容

不要把部署主机 PHP 路径、数据库密码、上传文件、运行时缓存、队列锁和站点域名写入共享模板或升级 SQL。模板开关和构建制品属于发布配置，不能通过业务数据表偷偷改变生产权限。
