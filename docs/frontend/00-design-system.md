# 前端设计规范

本规范服务于官网、客户中心、购物车和后台二开。当前项目使用 ThinkPHP 模板和已编译
后台资源；这里记录可复用的布局和交互约束，具体颜色、字体和品牌图片仍以当前主题为准。

首批新模板的断点、字号、间距、控件和表格密度已在[组件规格](19-component-interaction-contract.md)定义；具体页面文字线框见[首批样板](24-first-batch-page-specs.md)。这些是新布局方案，未经过浏览器视觉验收，不代表当前页面尺寸。

## 页面外壳

| 页面类型 | 桌面布局 | 移动端布局 |
| --- | --- | --- |
| 官网 | 顶部导航、内容区、页脚 | 导航折叠，内容单列 |
| 客户中心 | 顶部账户区、左侧导航、主内容区 | 左侧导航改为抽屉或折叠区，表格允许横向滚动 |
| 购物车 | 商品/配置主区 + 订单摘要 | 配置单列，摘要固定在操作区域附近 |
| 后台 | 顶部工具区、侧栏菜单、表格或表单内容区 | 以现有编译资源行为为准，优先保证表单和表格可操作 |

## 通用组件

按钮、表单、表格、分页、标签、弹窗、通知、加载状态、空状态和错误状态应优先复用
当前主题已有样式和脚本。新增组件必须说明：显示条件、禁用条件、提交中状态、成功后
行为、失败提示和移动端表现。

## 数据显示

- 金额、账单状态、服务状态和库存以服务端返回为准，前端不得自行推导最终结果。
- 长文本、错误信息和上游返回要限制长度并转义。
- 列表必须定义加载中、空数据、请求失败、无权限和会话过期状态。
- 破坏性操作必须二次确认，并在成功后刷新相关列表或明确跳转。

## 响应式验收

至少检查桌面宽屏、普通笔记本宽度和手机宽度。重点检查导航、表格、支付区、弹窗、
表单、代码/密码显示、长商品名称和工单附件。不能只通过改变浏览器宽度判断完成，需
实际点击主要操作。

## 安全和可访问性

- 模板输出默认转义；富文本只在明确的可信边界渲染。
- 表单保留框架 Token、HTTP 方法和隐藏字段；不要从前端传入的 `uid`、价格或权限决定
  业务结果。
- 键盘焦点、错误提示、按钮禁用和颜色对比应可理解；不能只用颜色表达状态。
- 生产页面删除 `{debug}`、测试域名、源映射密钥和敏感调试数据。
