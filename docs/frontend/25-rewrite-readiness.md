## 实际待解决事项

1. **新后台工程与构建**：用户已确认没有原工程源码，确定根据旧页面排版/交互和真实接口新建后台。压缩包只有编译资源，不再等待恢复原工程；需要落实新工程源码、技术栈、锁文件、实际命令和完整制品清单。旧入口未直接引用 config.js，需追踪旧 API/base/hash/rewrite，并明确新入口与 API 的对应及兼容方式。
2. **部署扩展缺口**：admin.php 无条件 include app/res/route/res.php，但当前 checkout 缺此文件。副本本次登录/客户读取 HTTP 已成功，缺口没有阻断所测路径；原因和其他路径仍需核对，不推定依赖已修复，也不简单删 include。
3. **后台模板解析**：ViewAdminBase 先通过 view_tpl_file 读 themes/web，Think 驱动 fetch 使用 public/<adminAddress>/themes；必须技术验证或有针对性兼容方案，不能假定 admin_default_theme 已解决新后台切换。
4. **运行时权限**：API 的 AdminBase 与 View* 基类不同。只读查询发现客户规则存在名称大小写差异、summary 有重复匹配记录；普通角色授权、菜单及部门/销售范围仍未导出验证。客户编辑还需要 Common 辅助选项规则，不以超级管理员成功代替验收。
5. **既有接口行为**：部分有副作用 GET、非幂等/不逐项返回的批量操作、模块队列 200 无 task_id、部分退款仍写 Refunded。新模板必须如实呈现，需要后端改进时单独立项。
6. **业务分支与统计验证**：资源商品、上游/DCIM、退款/支付、信用额版本、报表跨币种及空数据等需要沙箱与隔离数据库，不能以静态方法存在判运行成功。
7. **测试环境尚未完整隔离**：此前预检核实副本 APP_PHP=/www/server/php/72/bin/php（7.2.33），站点 FPM 和活动 worker 使用 PHP 7.2，但两条 Cron 定义用默认 php，指向 PHP 8.0；本轮浏览器观察未刷新这些证据。副本与生产数据库配置目标不同，但账号权限等未核实；Session 均固定 /tmp/session，通知/外部服务未隔离。用户提供入口及账号后已做一次旧后台登录与导航，未放行资料写入或完整样板验收。
8. **客户编辑契约缺口**：profile 不返回 city/region/avatar；保存需要保留已读字段、有效元数据和 custom 的表单结构。profilePost 在主资料更新后校验自定义字段，没有整段事务；失败可能部分保存，必须保留草稿并重新读取。Hook 的客户 ID 读取也存在已 unset 参数问题，需要样板验证或后端另案修复。

## 建议实施顺序

1. 先建立隔离环境并核实 APP_PHP、扩展和入口，保留实际配置在环境中。
2. 按样板 F01–F06 做前台子主题首批；后台优先落实 A01–A03 的登录→客户列表→资料编辑工程和环境，按 26 文档跑通样板，再推进工单等模块。
3. 使用 UI-FIXTURE-1 跑首批验收和回滚，记录响应、权限和截图，更新状态表。
4. 再分批冻结后台商品/财务/模块及其他 229 条路由记录的具体页面关系，完成对应契约后放行该批，不等待全站高保真稿，也不一次放行全站。
