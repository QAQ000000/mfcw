# 新模板重做契约

前台和后台新模板必须先完成页面契约，再开始批量改模板。视觉稿只能决定表现，不能改变
现有路由、权限、金额、状态和接口语义，除非另有业务变更计划。

当前已有[后台路由全表](22-admin-route-inventory.md)、[两套页面对应](23-admin-page-crosswalk.md)及[首批文字线框](24-first-batch-page-specs.md)。全表是静态记录，部分对应和页面契约仍未冻结；[开工状态](25-rewrite-readiness.md)列出真实验证与后续补齐门槛，不能把文档分类齐全当作可全面开工。

实施时同时使用以下配套契约： [页面接口契约](13-page-api-contract.md)、[后台权限矩阵](14-admin-permission-matrix.md)、[状态与操作矩阵](15-domain-state-action-matrix.md)、[架构与构建](16-frontend-architecture-build.md)、[迁移与回滚](17-template-migration-cutover.md)、[测试验收](18-frontend-test-acceptance.md)、[组件交互](19-component-interaction-contract.md)、[国际化与 SEO](20-i18n-content-assets-seo.md) 和[数据兼容迁移](21-data-compatibility-migration.md)。

## 每个页面必须交付

1. 页面名称、路由、HTTP 方法和登录/权限要求。
2. 桌面端、移动端布局图或线框图，标出公共区、内容区、操作区和错误提示区。
3. 模板文件、控制器、接口和关键字段映射。
4. 操作按钮的显示条件、禁用条件、确认文案、请求中状态和完成后行为。
5. 加载、空数据、失败、无权限、会话过期、处理中和重复提交状态。
6. 影响的语言键、静态资源、主题继承和缓存清理步骤。
7. 验收账号、测试数据、浏览器宽度和可复现的验收步骤。

## 前台重做边界

- 官网保持公开内容、SEO、文章和产品入口；客户中心保持客户会话和客户数据边界。
- 购物车保持产品配置、价格重算、库存、优惠码、结算和支付流程，不把视觉金额当成最终金额。
- 服务页面保持主机归属校验、服务器模块动作、异步任务和敏感信息保护。
- 财务页面保持账单、余额、支付回调和退款状态；任何支付按钮都必须对应真实账单状态。

## 后台重做边界

- 保持 `admin_application` 前缀、管理员登录、二次验证、菜单权限和接口权限一致。
- 列表页统一定义筛选、分页、批量操作、空态和导出；详情页统一定义返回、保存、审计日志
  和失败回填。
- 客户、订单、商品、财务、工单和上游资源页面必须分别记录读权限、写权限和高风险操作
  权限，不能只依赖菜单隐藏。
- 如果后台前端源码不在仓库，只能先做模板契约和后端接口适配；不得把压缩包直接当作长期
  可维护源文件。

## 页面验收矩阵

| 检查项 | 前台 | 后台 |
| --- | --- | --- |
| 未登录/无权限 | 登录跳转、数据不泄漏 | 登录页、权限拒绝、菜单与接口一致 |
| 加载/空态/错误 | 列表、表单、支付、服务控制 | 表格、统计、表单、批量操作 |
| 重复提交 | 订单、支付、工单、主机操作 | 保存、删除、批量变更、上游动作 |
| 移动端 | 登录、商品、购物车、账单、工单、服务 | 至少验证核心列表和表单可操作 |
| 安全 | Token、金额、客户 ID、附件、敏感凭据 | 管理员权限、审计、敏感字段和下载 |
| 回归 | 默认主题、子主题、语言、真实客户会话 | 有权限/无权限管理员和真实业务数据 |

## 分批实施

建议顺序：

1. 先锁定全局设计系统和公共布局。
2. 重做登录、客户中心首页、商品/购物车、账单支付和服务详情。
3. 重做工单、认证、内容和扩展页面。
4. 重做后台公共外壳，再按客户、业务、财务、商品、工单、资源分组迁移。
5. 每一批都保留旧模板可回退入口，完成真实会话验收后再删除旧实现。
